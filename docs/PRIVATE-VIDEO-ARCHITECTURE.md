# دروسي — تصميم الفيديو الخاص والنشر التلقائي

الحالة: تصميم معتمد، **ليس خدمة منشورة أو نظام صلاحيات فعليًا بعد**.

## الخدمات المختارة
- Cloudflare Stream: رفع وتحويل وبث فيديوهات HLS/DASH؛ يجب تفعيل requireSignedURLs للفيديوهات المدفوعة.
- Cloudflare Workers: واجهة API، تحقق الصلاحيات وإصدار رموز المشاهدة القصيرة؛ كل مفاتيح Stream محفوظة كـ Workers secrets.
- Cloudflare D1: فهرس الدروس والفيديوهات، اشتراكات الطلاب، وسجل عمليات النشر.
- هوية المستخدم: موفر مصادقة موثوق مع تحقق JWT على الخادم، ويجب اختيار موفر وتكوينه قبل الإطلاق. لا تعتمد على PIN المعلم الموجود حاليًا في JavaScript.
- GitHub Pages/Capacitor: واجهة الطلاب فقط، لا تتصل بـ Stream API مباشرة.

## دورة حياة الفيديو
1. يسجل المعلم الدخول عبر هوية موثقة، ويُتحقق من دوره على الخادم.
2. يختار الصف/المادة/الوحدة/الدرس، ويرسل POST /api/admin/videos/upload-intent.
3. يتحقق Worker من صلاحية المعلم وينشئ رابط رفع مباشر قصير الأجل من Cloudflare Stream. لا يمر ملف الفيديو عبر GitHub أو Worker.
4. يرفع المتصفح الفيديو مباشرة إلى Stream؛ يُحفظ سجل video في حالة uploading.
5. يؤكد webhook موقّع من Stream اكتمال المعالجة (مع التحقق من المصدر وتجنب التكرار)، وتصبح الحالة ready.
6. يراجع المعلم العنوان والدرس والظهور، ثم POST /api/admin/videos/:id/publish.
7. يكتب Worker تحديثًا ذريًا إلى قاعدة البيانات؛ يعرض GET /api/catalog للطلاب الدروس المنشورة فقط.
8. عند المشاهدة، يطلب الطالب POST /api/lessons/:id/playback؛ يتحقق Worker من الحساب والاشتراك وحالة النشر، ويصدر signed playback token قصير الصلاحية. يمنع التخزين المؤقت لرد الرمز.
9. عند انتهاء الاشتراك أو سحب النشر يتوقف إصدار رموز جديدة؛ لا يمكن سحب الرموز المصدرة سابقًا قبل انتهاء صلاحيتها.

## واجهات API المقترحة
- POST /api/admin/videos/upload-intent — معلم مخول؛ بيانات الدرس واسم الملف ونوعه وحجمه
- GET /api/admin/videos — فيديوهات المعلم وحالة المعالجة
- PATCH /api/admin/videos/:id — تعديل العنوان/الوحدة/الدرس/الترتيب
- POST /api/admin/videos/:id/publish — نشر بعد التأكد من جاهزية الفيديو
- POST /api/admin/videos/:id/unpublish — إيقاف النشر
- POST /api/webhooks/stream — تحديث حالات الفيديو بعد التحقق من webhook
- GET /api/catalog — فهرس المحتوى المنشور دون أسرار أو playback tokens
- POST /api/lessons/:id/playback — إصدار token بعد التحقق من صلاحية الطالب
- GET /api/admin/audit — سجل النشر والإيقاف والتعديلات للإدارة

## نموذج البيانات
users(id, auth_subject, role, status, created_at)
teacher_scopes(teacher_id, grade, subject)
courses(id, grade, subject, semester, title, status)
units(id, course_id, title, sort_order)
lessons(id, unit_id, title, type, status, sort_order, is_free)

enrollments(id, user_id, course_id, status, starts_at, ends_at)
audit_events(id, actor_id, action, target_type, target_id, created_at)

## الأمان والخصوصية
- كل صلاحية تُتحقق على الخادم، وليس فقط بإخفاء أزرار الواجهة.
- منع تخزين stream_uid مع token دائم في ملفات عامة؛ stream_uid وحده ليس سرًا لكنه لا يمنح صلاحية مشاهدة فيديو مقيّد.
- مفاتيح API في Workers secrets؛ لا ترفعها إلى GitHub.
- حدود رفع الملفات ومعدلات الطلبات، تحقق من MIME والحجم، مراجعة محتوى المعلم، سجلات تدقيق.
- CORS محدد على نطاق دروسي؛ HTTPS إلزامي؛ استجابات المصادقة والمشاهدة Cache-Control: no-store.
- لا يمكن منع تصوير الشاشة بالكامل؛ signed URLs تقلل مشاركة الروابط ولا تمنع تسجيل المحتوى.
- إظهار حالة رفع/معالجة/جاهز/منشور/فشل، مع إمكانية إعادة المحاولة دون تكرار.
- النسخ الاحتياطي لـ D1 والاحتفاظ بسجلات الإصدارات، واختبار الاستعادة.

## ترحيل دروسي الحالية
- لا تغير مفتاح localStorage: durusi_v1.
- احتفظ بالروابط الحالية (YouTube/Vimeo/MP4) كـ legacy حتى يتم استيرادها أو استبدالها.
- اعمل mapping بين معرفات الدروس الحالية ومعرفات قاعدة البيانات الجديدة، مع سجل مراجعة يدوي للحالات المتعارضة.
- لا تعتبر content.json مصدر الحقيقة للمحتوى المدفوع بعد تشغيل الخادم؛ يبقى للعرض العام والتوافق المؤقت.
- لا تفعّل النشر المدفوع حتى تنجح اختبارات: هوية الطالب، اشتراك منتهي، صلاحية معلم، فيديو غير منشور، رمز منتهي، منع الوصول المباشر.

## خطوات التنفيذ والإطلاق
1. إنشاء حساب Cloudflare وتفعيل Stream وWorkers وD1 وتحديد النطاق؛ هذه الخدمات **لم تُنشأ بعد**.
2. اختيار موفر مصادقة وتكوينه، وتهيئة الأسرار والبيئات (staging/production).
3. تنفيذ Worker وD1 migrations، ورفع مباشر آمن وwebhook.
4. ربط لوحة المعلم وواجهة الطالب بـ API، وإزالة الاعتماد على PIN ثابت في الإدارة الحقيقية.
5. اختبار فيديو مجاني ومدفوع، وتجربة مستخدم على iOS وAndroid والويب.
6. إعداد الاشتراكات والدفع وفق المتطلبات القانونية والتجارية قبل تحصيل أي رسوم.

## معايير القبول
- معلم مخول يرفع فيديو، يرى تقدم المعالجة، ثم ينشره من داخل المنصة دون تعديل GitHub.
- طالب مشترك يستطيع المشاهدة؛ غير المشترك يتلقى 403 دون token.
- لا تظهر أسرار Cloudflare أو روابط رفع إدارية في الواجهة العامة.
- يبقى تقدم الطلاب المحلي وبياناتهم الحالية محفوظًا أثناء الترحيل.
