# منصة دروسي — iOS + Android + Web PWA

هذه الحزمة تنقل واجهة دروسي الحالية إلى بنية متعددة المنصات من قاعدة ويب واحدة:

1. **iPhone وiPad:** تطبيق iOS/iPadOS عبر Capacitor.
2. **Android:** تطبيق Android عبر Capacitor، ويمكن إنتاج APK للتجربة وAAB للنشر.
3. **الموقع:** نسخة PWA قابلة للإضافة إلى الشاشة الرئيسية، مع Service Worker وأيقونات التطبيق.

## محتويات المشروع

- `www/`: ملفات الويب التي تعمل داخل التطبيقين وعلى الموقع.
- `capacitor.config.ts`: هوية التطبيق وإعدادات Capacitor.
- `package.json`: الاعتماديات وأوامر العمل.
- `www/content.json`: ملف محتوى افتراضي فارغ حتى لا يفشل طلب المحتوى عند عدم وجود ملف منشور.
- `www/manifest.json` و`www/sw.js`: تثبيت PWA والتخزين المؤقت.

## إعداد المشروع

يتطلب Node.js 20 أو أحدث، واتصالًا بالإنترنت عند تثبيت الحزم:

```bash
npm install
npx cap add ios
npx cap add android
npx cap sync
```

إذا كان مجلدا `ios/` و`android/` موجودين بالفعل، لا تكرر `cap add`؛ استخدم:

```bash
npx cap sync
```

## بناء iPhone وiPad

يتطلب جهاز Mac مع Xcode. افتح المشروع:

```bash
npx cap open ios
```

من Xcode اختر فريق التوقيع (Signing Team) وحزمة التطبيق المناسبة، ثم اختبر على جهاز فعلي أو Simulator. لإصدار IPA للتوزيع يلزم توقيع Apple وحساب مطور وفق طريقة التوزيع المطلوبة. لا يمكن إنشاء IPA موقّع صالح للتثبيت من بيئة لا تحتوي على Xcode وشهادات التوقيع.

## بناء Android

يتطلب Android Studio وJDK المدعوم من إصدار Gradle الذي سيولّده Capacitor:

```bash
npx cap open android
```

للتجربة يمكن إنشاء APK من Android Studio. وللنشر على Google Play أنشئ Android App Bundle (AAB) ووقّعه بمفتاح إصدار محفوظ بأمان.

## نشر الموقع وإضافته إلى الشاشة الرئيسية

ارفع محتويات `www/` إلى جذر GitHub Pages أو أي استضافة HTTPS. لا ترفع مجلد `www` نفسه كمجلد فرعي إذا أردت أن يكون رابط الموقع في جذر النطاق.

- iPhone/iPad: افتح الرابط في Safari ثم مشاركة ← إضافة إلى الشاشة الرئيسية.
- Android: افتح الرابط في Chrome ثم القائمة ← تثبيت التطبيق أو إضافة إلى الشاشة الرئيسية.

## تنبيهات قبل الإطلاق العام

- هذه الحزمة هي **قاعدة مشروع متعددة المنصات** وليست ملفي IPA وAPK نهائيين.
- بيانات الطالب الحالية تحفظ محليًا باستخدام `localStorage` تحت المفتاح `durusi_v1`. تبقى البيانات على الجهاز نفسه ولا تتزامن تلقائيًا بين الهاتف والتابلت.
- وضع المعلم في النسخة الحالية يعتمد رمزًا ثابتًا داخل JavaScript (`2026`)؛ هذا ليس نظام مصادقة آمنًا ويجب استبداله بخادم وصلاحيات قبل الإطلاق العام.
- لم تتم إضافة قاعدة بيانات سحابية أو حسابات فعلية؛ يجب تصميمها وترحيل البيانات إليها بخطة منفصلة مع اختبار عدم فقد البيانات.
- راجع محتوى المواد والأسئلة مع المنهج الرسمي قبل الاعتماد التعليمي.
- رابط `SITE_URL` داخل `www/index.html` ما زال قيمة افتراضية؛ اضبطه فقط إذا أردت تحميل `content.json` من عنوان ويب خارجي. الملف المحلي المرفق يوفر استجابة افتراضية.

## الحفاظ على بيانات النسخة السابقة

لا تحذف بيانات التطبيق القديمة ولا تغيّر `KEY='durusi_v1'` في هذه المرحلة. عند اختبار التطبيق الأصلي والنسخة الجديدة على نفس الجهاز والمتصفح، تحقق من استمرار ظهور تقدم الطالب. تثبيت تطبيق Capacitor لا يضمن تلقائيًا نقل بيانات المتصفح المثبتة سابقًا إلى مساحة التطبيق الأصلية؛ يلزم اختبار ترحيل منفصل إذا كان ذلك مطلوبًا.

## تحديث حزمة البناء الآلي

أضفنا إجراءات GitHub Actions:

- `pages.yml`: نشر موقع PWA بعد نجاح الفحص، ويتطلب تفعيل **Settings → Pages → Build and deployment → GitHub Actions**.
- `android-debug.yml`: بناء APK تجريبي غير مخصص للنشر في المتجر، ثم تنزيله من **Actions → Artifacts** بعد نجاح المهمة.
- `ios-check.yml`: فحص بناء iOS على محاكي Mac، **ولا ينتج IPA موقّعًا**. لإصدار IPA يلزم Xcode والتوقيع من حساب Apple مناسب.

يُفضّل تشغيل `npm install` وإنشاء `package-lock.json` ورفعه لضمان تثبيت نسخ ثابتة. حاليًا تستخدم إجراءات GitHub `npm install` لأن إنشاء ملف القفل لم ينجح في هذه البيئة بسبب تعذّر الوصول إلى npm.

**مهم:** لم يتم اختبار إجراءات البناء على GitHub بعد، وقد تتطلب تعديلات حسب إصدارات Capacitor وXcode وAndroid SDK المتاحة.

### اختبار سريع محلي

```bash
npm run check
npm run web:preview
```

افتح `http://localhost:8080` في المتصفح. وضع PWA الكامل يحتاج HTTPS عند النشر. لا تنسَ أن مفتاح `durusi_v1` يخزن بيانات كل جهاز محليًا؛ تثبيت تطبيق Capacitor لا ينقل تلقائيًا بيانات Safari/Chrome.

## بناء IPA غير موقّع للتوقيع بواسطة E-Sign

- افتح GitHub → Actions → **Build iOS Device IPA (unsigned)** → Run workflow.
- بعد نجاح العملية افتح التشغيل ثم **Artifacts** وحمّل `Durusi-iOS-iPadOS-unsigned-IPA`.
- فك ضغط ملف الـ Artifact للحصول على `Durusi-unsigned.ipa`، ثم استورده في E-Sign.
- وقّع IPA بشهادة صالحة وملف provisioning profile متوافقين مع معرّف التطبيق `com.durusi.app` والجهاز المعني. قد يتطلب التوقيع تعديل المعرّف بحسب ملف التعريف؛ نجاح التثبيت ليس مضمونًا لكل الشهادات.
- هذا المسار يبني **لأجهزة iPhone وiPad الفعلية** (`iphoneos`)، وليس لمحاكي iOS. البناء هنا غير موقّع، ولا يتيح تثبيت التطبيق دون توقيع صحيح.
- لا ترفع ملفات الشهادات أو كلمات مرورها إلى المستودع العام.
